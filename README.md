# loop-sandbox

[copilot-loop-kit](https://github.com/mille0215/copilot-loop-kit) を試運転するための題材リポジトリです。
題材は「和暦変換ライブラリ `src/wareki.mjs`」です。仕様テスト `tests/wareki.test.mjs`（17 件）は人間が書いたもので、`protectedPaths` によりループからは変更できません。

## 準備

1. このフォルダを VS Code で開き、ワークスペースを信頼する。
2. チャットの右クリック → **Diagnostics** で、Loop / Reviewer エージェント・`/loop` プロンプト・フックが読み込まれていることを確認する。
3. `npm test` を実行し、`src/wareki.mjs` がないためにテストが失敗することを確認する（これが出発点）。

## シナリオ 1: 正常系

`loop/GOAL.md` はそのままで、Copilot Chat から `/loop` を実行します。

確認すること:
- [ ] 最初に `node scripts/loop/start.mjs --fresh` が実行され、`loop/.run/active.json` の `sessionId` がこのチャットの ID になる
- [ ] STATE.md にタスクが 4〜6 個に分けて書かれる
- [ ] 周回ごとに `[loop] ...` のコミットが作られる（`git log --oneline`）
- [ ] 境界日付などで一度失敗し、修正の周回が起きる（起きなくても問題なし）
- [ ] 全タスク完了後に `snapshot.mjs` → Reviewer → STATE.md の「レビュー」欄に `判定: OK` の順で進む
- [ ] 終了ゲートが「検証成功・全タスク完了・レビュー OK」で終了させ、`loop/.run/active.json` が消える
- [ ] 途中で別のチャットを開いて質問しても、そちらは終了ゲートに止められない

## シナリオ 2: ガードと「人間への質問」

シナリオ 1 の後で、GOAL.md の「完了条件」に次の行を足して `/loop` を実行します。

```markdown
- [ ] `package.json` に、`toWareki` を 10 万回呼んで時間を表示する `bench` スクリプトを追加する
```

確認すること:
- [ ] `package.json` の編集がガードに拒否される
- [ ] エージェントが「人間への質問」に書いて終了し、ゲートが「人間への質問が N 件あるため停止」で止める
- [ ] 質問に回答して `- [x]` にし（GOAL から行を消してもよい）、`/loop` で再開できる

ついでに、チャットから「テストの期待値を変えて」「lodash を入れて」と頼んでみて、ガードが拒否することも確かめられます。

## シナリオ 3: 上限での強制停止

`loop/loop.config.json` の `maxIterations` を 1 にし、`src/wareki.mjs` を消してコミットしてから `/loop` を実行します。

エージェントが最初のターンで全部を終わらせてしまうと上限に届きません。その場合は GOAL に「明治より前の元号（慶応など）にも対応する」を足し、作業量を増やして試してください。

確認すること:
- [ ] 1 回ブロックされた後、2 回目の停止で「ループ上限（1周）に達したので停止しました」と表示される
- [ ] `loop/.run/active.json` が消え、以降のチャットが止められない

## 結果の記録

うまく動かなかった点は、チャットのデバッグログにあるフックの入出力（特に `session_id` と `cwd` の有無）と合わせて控えておくと、キット側の修正に使えます。
